How remax knows an agent is there

The header shows ● watching or ✦ working when an agent is attending the review. Nothing tells remax directly — there is no connection between the two. It is a heartbeat written to the filesystem and read on a beat, so that no cleanup is needed when either side dies.

The whole mechanism

The heartbeat file

One file per writing process, named for its pid. Rewritten whole on every beat — the point of the write is the timestamp it leaves behind, not the bytes, which barely change. 

$XDG_STATE_HOME/remax/waiting/3452411
├─ name .... the writer's pid, so two processes never collide
├─ line 1 .. "working" | "waiting"
└─ rest .... one repository path per line (a story watches several)

working
/home/you/work/flipstone/remax

Both writers can be live at once, and usually are: the long-lived remax watching says working while a list --wait says waiting. Waiting wins when both are present, because being blocked on the reviewer is the more specific fact.

Timings

WhatIntervalWhy that number
remax watching beat1 s Comfortably inside the 4 s staleness window, so a slow moment never blinks.
list --wait beat400 ms It is already polling the punch list at that rate; the heartbeat rides along.
Considered stale after4 s Long enough to tolerate a missed beat, short enough that a dead agent goes dark while you are still looking at the header.
Session poll420 ms / 1.5 s Quick while somebody is attending — it doubles as the animation frame rate — and slow when nobody is, so an unattended session is not waking up to redraw something that is not on screen.

Nothing on either side has to be told anything. remax never learns that an agent exists; it reads a directory and believes recent timestamps. That is the whole design: the failure mode of every component is silence, and silence reads correctly as “nobody is there”.

What it still cannot see

An agent that is alive but not paying attention. The process is running and beating, so the mark stays lit. Context exhausted, stuck on another task, waiting on a human elsewhere — all of it looks like working.

A watch whose parent outlives the agent session. The orphan check catches a dead parent, not an idle one. If the shell that started it survives the agent, so does the mark — which is why the skill kills it wherever it kills the wait.
